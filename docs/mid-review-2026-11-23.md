# 중간 점검 지시서 (2026-11-23)

진행 보고서(v0.1.7 시점)와 코드를 대조한 결과다. 위에서부터 순서대로 처리한다.
항목마다 끝나면 케이스를 추가하고, 전체 테스트를 돌린 뒤 시안에게 확인을 받고 다음으로 넘어간다.
스키마나 데이터 형식이 바뀌는 항목(3, 6)은 설계를 먼저 보여주고 승인을 받은 뒤 구현한다.

## 1. 같은 이름 판정을 alias 기준으로 (버그)

- 지금 `formats/common.lua`의 `count_names`는 일본어 이름(`c.name`)으로 같은 이름을 판정하고, 이름이 없으면 건너뛴다.
- 오리카는 `ko` 텍스트만 있어서 메인 덱 같은 이름 4장 제한과 루리그 덱 중복 금지가 전부 빠진다.
- **고칠 것:** 판정 키를 `cards.alias`로 바꾼다. alias가 0이면 cid를 쓴다. 포맷 판정의 `Deck.NameHasFormat`(같은 이름의 이전 카드)도 같은 키로 바꾼다.
- **케이스:** 일본어 이름이 없는 오리카 카드 5장 → 거부. alias로 이어진 두 cid를 합쳐 5장 → 거부.

## 2. 코어 DLL은 `has_core` 저장소에서만 (보안)

- 지금 `frame/core_loader.cpp`는 `repositories/*/bin/wxcore.dll`을 전부 훑고, 이름순으로 마지막 것을 쓴다. `config/configs.json`의 `has_core`를 보지 않는다.
- 오리카 팩 저장소에 dll이 섞여 있으면 그게 코어로 실행된다.
- **고칠 것:** `has_core: true`인 저장소의 `repo_path`에서만 dll을 찾는다. 여러 개면 configs.json에 적힌 순서를 따른다.

## 3. 시그니 클래스를 숫자 코드로 (설계 먼저, 승인 후 구현)

- 지금은 `cards.class`가 「精武：遊具」 같은 문자열 JSON이고, 스크립트가 문자열을 비교한다.
- 공식 DB의 시그니 클래스 문자열은 71종이다. 「系統：種族」 두 부분이다.
  - 系統(왼쪽): 精武·精械·精像·精生·精羅, 奏武·奏械·奏像·奏生·奏羅 등.
  - 種族(오른쪽): 40종 정도.
  - 콜론 없는 클래스도 있다(예: 「奏元」).
- **판정 규칙** (용어집 「クラス」 항목):
  1. 「：」 좌우가 완전히 같아야 같은 클래스다. 예: ＜精像：悪魔＞와 ＜奏像：悪魔＞는 다른 클래스.
  2. 효과가 오른쪽(種族)만 쓰면 系統과 상관없이 해당한다. 예: ＜悪魔＞는 ＜精像：悪魔＞와 ＜奏像：悪魔＞ 둘 다.
  3. 효과가 왼쪽(系統)만 쓸 수도 있다. 예: ダーク・コグネイト(WX20-007)의 ＜精像＞는 精像：天使, 精像：悪魔 등 精像 계열 전부이고, 奏像은 해당하지 않는다.
- **방향:**
  - 클래스 하나를 (系統 ID, 種族 ID) 쌍으로 저장한다. 種族이 없으면 0.
  - 시그니 한 장이 클래스를 여러 개 가질 수 있고, 오리카와 콜라보로 種族이 계속 늘어난다. 그래서 비트마스크가 아니라 쌍의 목록으로 저장한다.
  - 상수 표: `SYS_SEIZOU`(精像) 같은 系統 상수와 `RACE_YUGU`(遊具) 같은 種族 상수.
  - 판정 API 하나로 세 경우를 다 처리한다. 예: `Card.IsClass(c, sys, race)`에서 sys나 race 중 하나는 0(아무거나)을 허용한다.
- 표기 흔들림과 데이터 이상도 정리한다. 예: 「ウェポン」/「ウエポン」, 「闘争派/奏羅」 같은 값. 정오표(`guides/text/products/wixoss/faq/rule_errata`)의 클래스 수정도 반영한다.
- 루리그 타입(84종)은 계층이 없으니 단일 ID로 충분할 것이다. 설계안에 같이 적는다.
- 설계안 정리 내용: DB 칼럼 형식, 상수 표 위치(오리카 팩이 系統·種族을 추가하는 방법 포함), 스크립트 API. 이걸 시안에게 보여준다.

## 4. `aux.ClassFilter`

- 3이 정해지면 `<遊具>` 필터(스크립트 3개에 중복)를 일반 헬퍼로 뽑는다. 예: `aux.ClassFilter(0, RACE_YUGU)`, `aux.ClassFilter(SYS_SEIZOU, 0)`.
- 케이스로 넣을 것:
  - ＜遊具＞ 필터: 精武：遊具와 奏武：遊具 둘 다 통과
  - ダーク・コグネイト의 ＜精像＞: 精像 계열은 통과, 奏像 계열은 거부

## 5. 빠진 룰 메커니즘 (카드풀 확장보다 먼저)

1단계 목표("카드가 적어도 메커니즘은 전부")에서 남은 것들이다. 아래 순서로 한다. 각각 아카이브 용어집·FAQ 근거를 케이스에 적는다.

1. 「効果を受けない」, 「새로 얻지 못한다」 (イレイズ・ルフラン FAQ 3 포함)
2. `EFFECT_GRANT`로 지속 효과(【常】) 부여
3. 바이러스(감염 상태, 존 이동 시 해제)
4. 리미트 어퍼(코인·배리어와 같은 표식 취급)
5. 붙는 카드 상한(악세·참)
6. 그로우 조건
7. 繭の部屋: 금지·2장 제한·동시 사용 제한 목록, 기본 적용, 방 설정으로 끄기

## 6. 덱 파일에 일러 idx (인쇄본 고르기 넣을 때)

- 지금 덱 파일은 카드 번호로 카드를 가리킨다. 공식 카드는 괜찮지만, 오리카는 같은 카드 번호에 그림이 여러 장일 수 있다.
- 프레임에 「인쇄본 고르기」를 넣을 때, 덱 형식을 cid + idx로 바꾼다.
- 기존 덱 파일(카드 번호 형식)은 읽을 때 자동으로 변환한다.
